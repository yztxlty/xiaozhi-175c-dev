# YGSoul 圆形触摸屏设备端 UI 设计规范 V1.0

## 1. 项目目标

为 YGSoul AI 陪伴设备设计一套完整的圆形触摸屏 UI = User Interface（用户界面）。

目标硬件：
- Waveshare ESP32-S3-Touch-AMOLED-1.75C
- 屏幕尺寸：1.75 英寸
- 分辨率：466 × 466
- 屏幕形状：圆形
- 显示类型：AMOLED
- 支持触摸
- 产品定位：AI 陪伴、情绪陪伴、语音交互、拟人化角色

设计目标：

1. 强调“陪伴感”，而不是传统工具型智能硬件。
2. AI 角色必须成为整个 UI 的视觉核心。
3. 充分利用圆形屏幕，而不是将手机矩形 UI 强行塞入圆屏。
4. 页面尽量简单，每个页面只突出一个主要任务。
5. AI 对话需要具有“活着”的感觉，包括表情、呼吸、眨眼、嘴型、波纹等动态反馈。
6. 整体风格要求科技感、治愈感、未来感，但不能过度炫技。

“幽灵 / 灵体型 AI 伙伴”

- 圆润柔软

- 大眼睛

- 小嘴
- 怀抱发光爱心
- 外围星光 / 光环 / 粒子
- 可爱，但不能过幼稚

主体颜色：

建议：

```text

+
浅蓝紫渐变
+
边缘蓝紫光晕
```

例如：

```text

#D5F8FF

#87EAF3

主体底部：
#84A8F8

边缘光：
#7B61FF

爱心：
#FF75AD
→
#FFB0D0
```

角色必须保持：

```text
同一轮廓
同一比例
同一视觉身份
```

```text
眼睛
嘴型
身体姿态
爱心亮度
周围粒子

```

不得每个页面重新画成不同角色。

# 29. 嵌入式实现建议

实际在 ESP32-S3 上实现 UI 时，不建议把角色做成一整张大型 GIF。

建议将角色拆分为：

```text
身体 Body
眼睛 Eyes
嘴巴 Mouth
爱心 Heart
光环 Glow
粒子 Particles
波形 Wave
```

优点：

1. 可独立控制眨眼、嘴型、呼吸、情绪变化。
2. 减少重复图片数据。
3. 更容易控制 PSRAM 与 Flash 占用。
4. 更容易根据 AI 状态机实时切换。
5. 更适合 LVGL 的局部刷新机制。
6. 后续增加新表情时无需重做整套全屏动画。

推荐状态驱动关系：

```text
IDLE
→ neutral / breathe / blink

LISTENING
→ listening eyes + cyan wave

THINKING
→ thinking eyes + purple particles

SPEAKING
→ mouth animation + voice wave + emotion

SLEEP
→ closed eyes + low brightness
```

这套角色系统应该作为 YGSoul UI 的长期视觉资产规范，而不是只为某一版 ESP32 固件临时制作。
