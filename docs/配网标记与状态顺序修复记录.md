# 配网标记与状态顺序修复记录

## 范围

2026-09-07，在本地 `main` 修改 ESP32S3 1.75C 配网入口与联网事件顺序；未修改 A100、小程序或服务端。

## 已确认原因与修复

| 原因 | 证据 | 最小修复 |
| --- | --- | --- |
| NVS 键 `pairing_reboot_pending` 超过 15 字符，写入触发断言重启，随后普通启动连接旧 Wi-Fi | 串口报 `ESP_ERR_NVS_KEY_TOO_LONG`，实际入口编译测试复现失败 | 保留业务常量名称，存储键改为 `pair_pending`；编译期校验长度，不修改底层格式 |
| `Settings` 在析构时提交，但此前在析构前调用不返回的重启函数 | 短键修复后，重启时持久化断言仍失败 | 使用局部作用域，先提交再重启 |
| 单独联网事件可清除配网状态并提前初始化协议 | 实际应用事件处理函数编译测试失败 | 本次有效配网成功回执负责退出；停止 BLE 后补发联网通知，覆盖回调先后顺序 |

NVS 的长度是底层存储约束，不是业务名称限制；禁止扩大 ESP-IDF 常量掩盖非法键。以后修改键名称必须通过编译检查与持久化测试。
